## 网页刷不出来（全部服务宕机 + vite 损坏）

### 现象
用户报"怎么又刷不出网页了"。排查发现 5173/8000 全部 NOT LISTENING（进程都没了，可能宿主环境重启/终端关闭）。且 `frontend/node_modules/vite` 损坏。

### 根因
1. **所有 dev server 都挂了**（前端 5173、后端 8000 都没在监听）——之前"宿主 8000 杀不掉"是沙箱隔离错觉，现在 8000 已 DOWN，可由本沙箱正常启动。
2. **vite node_modules 损坏**：`frontend/node_modules/vite/dist/node/chunks/` 只剩 `dep-*.js`，主入口缺失。重装 `npm install vite@5.4.21 --force` 后恢复正常（注意：stock vite 5.4.21 的 chunks 目录本来就只有 `dep-*.js`，**没有** `node.js`/`dist.js`，这是正常的；之前日志里的 `Cannot find module dist.js` 是某次损坏状态造成的，不是 vite 本来结构）。
3. **vite.config.js 缺 import**：之前"还原"配置时漏了 import，导致 `ReferenceError: defineConfig is not defined`，dev server 起不来。已重写为带 `import { defineConfig } from 'vite'` 与 `import uni from '@dcloudio/vite-plugin-uni'`，并去掉 UTF-8 BOM。

### 修复步骤（已验证）
1. `cd frontend && rm -rf node_modules/vite && npm install vite@5.4.21 --force`（host node E:/Node.js/node.exe）
2. `npm run postinstall`（patch-package 重应用 `@dcloudio/uni-h5-vue` 只读 slot 补丁 ✔）
3. 修正 `frontend/vite.config.js`（加 import、去 BOM）
4. 启动后端：`cd backend && .venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000`（后台，日志 backend8000.log）
5. 启动前端：`cd frontend && npm run dev:h5`（后台，日志 frontend5173.log）
6. 端到端验证：5173 登录 200 → 上传 200（item_id=11 占位标签）→ 清理 200 ✅

### 结论
手动填写衣物 bug 的修复（后端 os/fse 别名 + 前端表单显隐）此前已写入磁盘并验证；本次是把整套服务重新拉起使之可用。当前 5173/8000 均正常。
