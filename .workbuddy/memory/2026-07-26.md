# 2026-07-26

## 处理后端报错（ai-wardrobe-agent）

### 根因
用户跑 `pip install -r requirements.txt` 失败，报错：
`error: Microsoft Visual C++ 14.0 or greater is required` / `Failed to build chroma-hnswlib`
原因：在 **Windows + Python 3.12** 上，`chroma-hnswlib` 的 0.7.3 与 0.7.6 版本都**没有 win_amd64 的 cp312 预编译 wheel**（0.7.6 仅有 mac/linux cp312 wheel），pip 被迫从源码编译 hnswlib → 缺 MSVC。

### 修复措施
1. 在 `backend/` 建了隔离 venv（系统 Python 3.12），绕过编译：先装带 cp312 win_amd64 wheel 的 `chroma-hnswlib==0.7.5`，再以 `pip install chromadb==0.5.23 --no-deps` 安装 chromadb（0.7.5 与 0.7.3/0.7.6 API 兼容），其余依赖正常装。
2. `requirements.txt`：chromadb 0.5.0 → 0.5.23（仍走 0.7.6，但仅作版本标注；真正可用靠上面绕过方式）。
3. 修代码 bug：
   - `app/llm/embeddings.py`：`__init__` 漏了 `self.api_base = DEEPSEEK_API_BASE`，运行 `embed()` 会 `AttributeError`，已补上。
   - `app/models/__init__.py`：原本没导入模型类导致 `create_all` 不建表；且编辑失误把 `get_db` 缩进进 `Base` 类。已重写为模块级 `get_db` 并导入 User/ClothingItem/Conversation/AgentStep/Correction/PromptVersion。
4. 验证：uvicorn 启动成功，`/`、`/api/user/profile`、`/api/stylist/corrections` 正常返回；app.db 实际建出 6 张表。

### 给用户的可复现说明
- 直接用现成 venv：`backend/.venv/Scripts/activate` 后 `uvicorn app.main:app --port 8000`。
- 全新安装需绕过 hnswlib 编译：先 `pip install chroma-hnswlib==0.7.5`，再 `pip install -r requirements.txt --no-deps`（或 chromadb 单独 --no-deps）。更彻底的做法是安装 VS2019+ 生成工具（MSVC），那样原命令即可直接用。
