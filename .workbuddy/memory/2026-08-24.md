## 智谱 GLM 模型报错 503/timeout 排查（用户：为什么切智谱就报错）

### 根因
用户智谱账户开通的是**新版 2025 模型（GLM-4.5+/5.x）**，但配置端下拉里只有老 4 个（glm-4-flash/plus/air/flashx）。
- 老模型在用户账户下**根本不存在**（HTTP 503 "modelCode 不存在"）
- 部分老模型（如 glm-4-airx）走老网关，高峰期 60s 也回不来 → read timeout

**诊断手法**：用 `/api/paas/v4/models` 查账户实际可见模型 → 9 个新版模型（4.5/4.5-air/4.6/4.7/5/5-turbo...）
**用户在 DeepSeek/通义都正常** → 排除网络/账户 → 是模型名问题

### 改动（backend/app/llm/zhipu.py + frontend-web/src/views/config/Index.vue）
1. **配置端下拉改为用户账户真实可见模型**：去掉 glm-4-flash/plus/air，加 glm-4.5/4.5-air/4.6/4.7/5/5-turbo（保留 glm-4-flashx 作兼容）
2. **zhipu.py 默认模型** glm-4-flash → glm-4.5（用户账户里能用的最快稳定款）
3. **zhipu.py 错误信息增强**：捕获 error.code，加提示
   - 1301 余额不足 → 充值提示
   - 1302 rate limit → 1-2 秒重试提示
   - 1303 模型不存在 → 选用账户内可见的 4.5/5.x
   - 503/429 → 限流提示
4. **zhipu.py timeout** 60s → 90s（智谱 19-21 点高峰偶尔 60s 冷启动超）

## 本环境重启后端的坑（实测补充）
- PowerShell 工具对宿主托管的 8000 进程 `Stop-Process` 无权限，且 `Write-Host` 输出被吞（退出码 1 但可能实际已杀）。
- `wmic`/`tasklist` 被沙箱安全策略禁用（SYSTEM TOOL DISABLED）。
- 正确做法：用 PowerShell 工具只做 `Get-Process -Name python | Stop-Process -Force`（不嵌 netstat），再用 **Bash** 单独 `netstat -ano | grep :8000 | grep LISTENING` 确认；FREE 后用 Bash 后台 `uvicorn` 启动新实例。
- 不要在 Bash 里调 `powershell -Command ...`（安全策略拦截）。
